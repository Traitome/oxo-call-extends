## Concepts

- **Tool Overview**: Verkko (Finnish for "net, mesh, graph") is a hybrid genome assembly pipeline developed for telomere-to-telomere (T2T) assembly of accurate long reads (PacBio HiFi, Oxford Nanopore Duplex, HERRO-corrected ONT, or Hifiasm-corrected ONT) combined with Oxford Nanopore ultra-long reads.
- **Core Algorithm**: Verkko uses Canu to correct remaining errors in HiFi reads, builds a multiplex de Bruijn graph using MBG, aligns ONT reads to the graph using GraphAligner, progressively resolves loops and tangles (first with HiFi reads, then with aligned ONT reads), and finally creates contig consensus sequences using Canu's consensus module.
- **Workflow Engine**: Implemented as a Snakemake workflow, launched by a wrapper script that parses options and creates a `verkko.yml` config file.
- **Mandatory Inputs**: `-d <output-directory>` (working directory) and `--hifi <files>` (PacBio HiFi / ONT Duplex / corrected reads). `--nano <files>` (ONT ultra-long reads) is strongly recommended but optional (`--no-nano`).
- **Phasing via Rukki**: Verkko supports extended phasing using rukki with three information sources:
  - **Trio phasing**: `--hap-kmers h1 h2 trio` — h1/h2 are Meryl databases of homopolymer-compressed parental k-mers generated by Merqury's `hapmers.sh`.
  - **Hi-C phasing**: `--hic1 <R1> --hic2 <R2>` — left/right read pairs (order must match, no interlaced files).
  - **Pore-C phasing**: `--porec <files>` — Pore-C contact reads.
  - **Strand-seq phasing**: `--hap-kmers h1 h2 strandseq`.
- **Scaffolding Module**: Triggered when Hi-C or Pore-C data are provided. Uses telomere positions (detected via `seqtk telo`) to orient/scaffold contigs. Gap size reported as estimated value when <100K, otherwise always 100K N's. Not compatible with `--haploid`; use YaHS standalone scaffolder for haploid assemblies.
- **Telomere Detection**: Default vertebrate motif `CCCTAA`; override with `--telomere-motif` for other species (searched in both forward and reverse-complement).
- **Reference-Guided Scaffolding**: `--ref <path>` provides a reference of the same/closely related species as guidance only — NOT reference-based assembly.
- **Contaminant Screening**: `--screen <name> <fasta>` removes contaminant sequences from the main assembly and outputs a circularized canonical exemplar. Multiple `--screen` commands are additive. `--screen-human-contaminants` is a shortcut for rDNA + mitochondria + EBV.
- **User-Provided Paths**: `--paths <paths.gaf>` regenerates contigs from user-specified paths through the assembly graph (GAF format: `name >utig4-1<utig4-2 HAPLOTYPE1`); requires `--assembly <path>` and input reads.
- **Output Files**:
  - `assembly.fasta` — final assembly.
  - `assembly.homopolymer-compressed.gfa` — final graph in homopolymer-compressed space.
  - `assembly*csv` — coverage files; `assembly.scfmap` — name→graph node translation.
  - With phasing: `assembly.haplotype[12].fasta`, `assembly.colors.csv`, `assembly.paths.tsv`.
  - With screening: `assembly.<name>.fasta` and `assembly.<name>.exemplar.fasta`.
- **Computational Parameters**: `--local-memory` (default 64 GB), `--local-cpus` (default all), `--grid` (SGE/Slurm/PBS/LSF), `--snakeopts` (pass-through Snakemake options), `--cleanup`/`--no-cleanup`.
- **Per-Stage Resource Tuning**: `--<stage>-run <cpus> <mem_gb> <time_h>` for stages: `sto` (storage), `ovb` (HiFi overlap), `ovs` (combine overlaps), `red` (correction), `mbg` (graph build), `utg` (graph simplification), `spl` (ONT split), `ali` (ONT align), `pop` (ONT processing), `utp` (untip), `lay` (layout), `sub`/`par`/`cns` (consensus), `ahc`/`fhc`/`shc` (Hi-C pipeline).
- **Installation**: `conda create -n verkko -c conda-forge -c bioconda -c defaults verkko`. From source: requires GCC 9+, Rust 1.74+ (do NOT use the .zip download — missing git submodules).
- **Runtime Dependencies**: Python 3.5+, Snakemake (>= v7.0, < 8.0.1), GraphAligner, MashMap, Winnowmap. For Hi-C/PoreC: also Samtools, BWA, Minimap2, seqtk, networkx (>=2.6, <=3.5).

## Pitfalls

- **Snakemake version constraint**: Verkko requires Snakemake >= 7.0 and < 8.0.1. Snakemake 8.x changed the CLI/executor API and will break verkko. Pin with `conda install 'snakemake>=7,<8.0.1'`.
- **Large memory requirements**: Default `--local-memory` is 64 GB, which is insufficient for mammalian genomes. A human T2T assembly typically needs >128 GB; allocate accordingly or use `--grid` with cluster resources.
- **Polyploid genomes not supported**: Polyploid scaffolding and phasing are not yet supported. For haploid assemblies, Hi-C/PoreC scaffolding is also disabled (use YaHS instead).
- **Hi-C/PoreC tuned for human/primate genomes**: The phasing heuristics were tested mostly on human. For divergent species, adjust `--haplo-divergence` (default 0.05, max 0.2) and consider `--uneven-depth` if coverage is uneven.
- **Telomere motif is vertebrate-specific**: The default `CCCTAA` is the vertebrate canonical motif. Plants (e.g., `TTAGGG`) and other taxa must specify `--telomere-motif` or scaffolding will mis-anchor contigs.
- **rDNA tangles can join chromosomes**: Large rDNA arrays can form tangles that connect multiple chromosomes. `--no-rdna-tangle` disables the heuristic that tries to resolve them (use only if the heuristic causes issues).
- **`--ref` is guidance only**: The reference provided via `--ref` is NOT used for reference-based assembly; it only guides scaffolding order. Do not expect reference-level colinearity.
- **`--hap-kmers` requires homopolymer-compressed Meryl DBs**: k-mers MUST be counted in compressed space (use `meryl count compress`). Plain k-mer databases will produce incorrect phasing.
- **No pseudo-haplotype output**: Verkko outputs phased scaffolds only; no attempt is made to generate a primary or collapsed haplotype assembly.
- **GraphAligner / MashMap / Winnowmap must be in PATH**: If not found, use `--graphaligner`, `--mashmap`, `--winnowmap` to specify absolute paths, or symlink under `verkko/lib/verkko/bin/`.
- **Gaps in scaffolds are 100K N's by default**: When the estimated gap size is >=100K or cannot be estimated, verkko always reports 100K N's. This is intentional, not a corruption.
- **Restarting runs**: Use `--snakeopts "--dry-run"` before restarting to verify only expected steps will execute. `--snakeopts "--touch"` resets timestamps to avoid regenerating existing files.
- **Source download via .zip fails**: Downloading the GitHub .zip source breaks git submodules and will not compile. Use `git clone` instead.

## Examples

### Basic hybrid assembly (HiFi + ONT)
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz`
**Explanation:** Minimum viable run. `-d asm` creates the working directory; `--hifi` provides accurate long reads (PacBio HiFi / ONT Duplex / corrected); `--nano` provides ultra-long ONT reads for resolving repeats. Final assembly: `asm/assembly.fasta`.

### Assemble without ONT data
**Args:** `verkko -d asm --hifi hifi/*.fastq.gz --no-nano`
**Explanation:** `--no-nano` assembles using HiFi reads only. Repeats longer than the HiFi read length will remain unresolved, producing fragmented contigs. Useful for quick previews or small genomes.

### Skip Canu HiFi correction
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --no-correction`
**Explanation:** `--no-correction` skips the Canu correction step on HiFi reads. Speeds up the run but may reduce consensus accuracy; only recommended when input reads are already highly accurate (e.g., Q40+ HiFi).

### Limit local memory and CPUs
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --local-memory 128 --local-cpus 32`
**Explanation:** `--local-memory 128` caps usage at 128 GB; `--local-cpus 32` limits to 32 threads. Useful for shared servers.

### Trio phasing with Merqury hap-mers
**Args:** `verkko -d asm --hifi hifi/*.fastq.gz --nano ont/*.fastq.gz --hap-kmers paternal.hapmer.meryl maternal.hapmer.meryl trio`
**Explanation:** `--hap-kmers` specifies paternal and maternal haplotype k-mer databases (Meryl, homopolymer-compressed) generated by Merqury's `hapmers.sh`; `trio` enables phased assembly. Outputs phased contigs in `assembly.haplotype1.fasta` and `assembly.haplotype2.fasta`, with phase info in `assembly.colors.csv` and `assembly.paths.tsv`.

### Generate hap-mers with Merqury (prerequisite for trio phasing)
**Args:** `meryl count compress k=30 threads=32 memory=64 maternal.*fastq.gz output maternal.k30.meryl && meryl count compress k=30 threads=32 memory=64 paternal.*fastq.gz output paternal.k30.meryl && $MERQURY/trio/hapmers.sh maternal.k30.meryl paternal.k30.meryl`
**Explanation:** Builds compressed-space k-mer databases (k=30) for each parent with `meryl count compress`, then `hapmers.sh` produces `*.hapmer.meryl` files used by verkko's `--hap-kmers`. The child database is optional.

### Hi-C scaffolding with custom telomere motif
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --hic1 hic_R1.fastq.gz --hic2 hic_R2.fastq.gz --telomere-motif TTAGGG`
**Explanation:** `--hic1`/`--hic2` provide Hi-C read pairs for scaffolding (order must match); `--telomere-motif TTAGGG` specifies a plant telomeric repeat (default is vertebrate `CCCTAA`). Scaffolds are output in `assembly.fasta` with gaps as 100K N's.

### Pore-C phasing
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --porec porec.fastq.gz`
**Explanation:** `--porec` provides Pore-C contact reads for phasing and scaffolding. Pore-C typically yields longer-range contacts than Hi-C and often produces more contiguous phased assemblies.

### Hi-C with uneven depth and high divergence
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --hic1 hic_R1.fastq.gz --hic2 hic_R2.fastq.gz --uneven-depth --haplo-divergence 0.12`
**Explanation:** `--uneven-depth` disables coverage-based homozygous-node heuristics (useful for amplified or biased libraries); `--haplo-divergence 0.12` raises the maximum divergence tolerance from the default 0.05 for species more divergent than human (max 0.2).

### Screen for human contaminants (rDNA, mitochondria, EBV)
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --screen-human-contaminants`
**Explanation:** `--screen-human-contaminants` is a shortcut for `--screen rDNA rdna.fasta --screen mitochondria mito.fasta --screen EBV ebv.fasta`. Removes contaminant sequences from `assembly.fasta` and writes circularized exemplars to `assembly.rDNA.exemplar.fasta`, etc.

### Custom contaminant screening
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --screen plasmid plasmid_db.fasta --screen chloroplast chloro.fasta`
**Explanation:** Each `--screen <name> <fasta>` is additive and removes sequences matching the target. A canonical representative is identified by coverage and circularized when possible, output as `assembly.<name>.exemplar.fasta`.

### Reference-guided scaffolding
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --hic1 hic_R1.fastq.gz --hic2 hic_R2.fastq.gz --ref related_species.fa`
**Explanation:** `--ref` provides a related-species genome used only as scaffolding guidance (NOT reference-based assembly). Improves scaffold ordering when Hi-C signal is ambiguous.

### Generate contigs from user-provided graph paths
**Args:** `verkko -d asm_new --hifi hifi.fastq.gz --nano ont.fastq.gz --assembly asm --paths custom_paths.gaf`
**Explanation:** `--paths <paths.gaf>` regenerates contigs from user-specified paths through the existing assembly graph (`--assembly asm`). The GAF file uses lines like `name >utig4-1<utig4-2 HAPLOTYPE1` (forward/reverse-orientation nodes). The new output dir (`-d asm_new`) must differ from `--assembly`.

### Run on Slurm grid
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --grid --snakeopts "--cores 1000"`
**Explanation:** `--grid` submits compute jobs to SGE/Slurm/PBS/LSF; `--snakeopts "--cores 1000"` caps total cores across submitted jobs. The Snakemake workflow itself still runs locally.

### Customize Slurm partition and QOS
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --grid --snakeopts '--cluster "./slurm-sge-submit.sh {threads} {resources.mem_gb} {resources.time_h} {rulename} {resources.job_id} --partition=quick --account=verkko_asm --qos=verkko_qos"'`
**Explanation:** The `--snakeopts --cluster` string customizes job submission (partition/account/QOS). `{threads}`, `{resources.mem_gb}`, etc. are Snakemake placeholders filled per rule.

### Tune per-stage resources (e.g., consensus)
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --cns-run 8 32 2`
**Explanation:** `--cns-run <cpus> <mem_gb> <time_h>` overrides the default for the consensus stage. All `--*-run` options follow the same format. Default values are listed in `verkko.yml` after launch.

### Dry-run to inspect planned jobs
**Args:** `verkko -d asm --hifi hifi.fastq.gz --nano ont.fastq.gz --snakeopts "--dry-run"`
**Explanation:** `--snakeopts "--dry-run"` prints the job plan without executing. Recommended before restarting or after modifying intermediates to confirm only expected steps will run.

### E. coli test dataset (installation check)
**Args:** `curl -L https://obj.umiacs.umd.edu/sergek/shared/ecoli_hifi_subset24x.fastq.gz -o hifi.fastq.gz && curl -L https://obj.umiacs.umd.edu/sergek/shared/ecoli_ont_subset50x.fastq.gz -o ont.fastq.gz && verkko -d asm --hifi ./hifi.fastq.gz --nano ./ont.fastq.gz`
**Explanation:** Downloads the official E. coli K12 test dataset (24x HiFi, 50x ONT subsets) from the verkko team's object store and runs a full assembly. Use this to verify a fresh installation completes end-to-end.

### Install via conda
**Args:** `conda create -n verkko -c conda-forge -c bioconda -c defaults verkko && conda activate verkko`
**Explanation:** Creates an isolated conda environment pulling verkko and its binary dependencies (GraphAligner, MashMap, Winnowmap, MBG) from bioconda. Pin Snakemake manually if the default resolves to 8.x: `conda install 'snakemake>=7,<8.0.1'`.
